# Иллюстрации статей Telegraph

`telegra.ph/upload` отвергал иллюстрации сообщением `Unknown error`. Прежний код
после этого публиковал страницу только с текстом. Файлы из кеша меню не имели
публичного адреса, поэтому сами по себе не могли появиться внутри статьи.

Теперь статьи используют прямые HTTPS-адреса изображений из публичного
репозитория. В production URL закреплён за `RAILWAY_GIT_COMMIT_SHA`, поэтому
картинка относится к той же версии кода. В локальной среде без корректного SHA
используется публичная production-ветка. Публикуются только файлы изображений
из `assets/updates` и `assets/covers`; другие локальные файлы и симлинки наружу
не преобразуются в публичные ссылки. Секреты и Telegram file URL не используются.

Иллюстрации нужно заранее включить в Git. Результат публикации запрашивается
с `return_content=true`: код проверяет, что Telegraph сохранил все запрошенные
узлы `img`. При недостающем исходном файле или удалённой сервером иллюстрации
публикация не считается успешной. Это проверяет содержимое страницы, но не
заменяет проверку загрузки файлов через браузер.

`repair_member_images(db)` однократно редактирует существующую статью №18,
подставляя новые `18-profile.jpg` и `18-wallet.jpg`. Он не создаёт заменяющую
страницу при ошибке и не меняет текущий анонс или его закреп. Маркер успеха
записывается только после проверки возвращённых изображений. Сбой оставляет
возможность повторить попытку при следующем запуске.

В логах публикации доступны номер статьи, число иллюстраций и публичная ссылка.
Токен Telegraph в эти сообщения не попадает. После выпуска нужно открыть эту
ссылку, проверить наличие `figure/img` и HTTP-ответы всех изображений. Удаление
или приватизация GitHub-репозитория потребует переноса публичных иллюстраций.
