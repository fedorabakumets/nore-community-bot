# NORA Liquid Glass 2.0

Спецификация редизайна Telegram Mini App. Базовая версия для сравнения — `7ee91cf`. Область дизайна — пять основных вкладок и общие компоненты, которые они используют.

В релизе фон Telegram и дока `#111013` совпадает с прежней оболочкой. Внутренние стеклянные панели используют `rgb(34 30 37 / 88%)`, поднятые поверхности — `#252128`. Капля дока использует цвет буквы «О» во всех оформлениях.

Нора — сообщество внутри Telegram. Человек открывает приложение, чтобы узнать, что происходит, найти своих, записаться на встречу, получить предмет или посмотреть состояние профиля. На каждой вкладке первый экран должен давать ответ по её основной задаче. Визуальная подпись Норы — кремовое слово, красная «О» и капля в нижней навигации. Выразительные обложки остаются у встреч, сезонных предметов, музыки и игр.

## Цвет и материал

| Токен | Значение | Применение |
| --- | --- | --- |
| `--nora-bg` | `#0F0D11` | Фон приложения |
| `--nora-panel` | `rgb(28 24 31 / 88%)`, fallback `#1C181F` | Поверхности в потоке |
| `--nora-raised` | `rgb(37 33 40 / 94%)`, fallback `#252128` | Диалог поверх контента, выделенная поверхность |
| `--nora-ink` | `#FFF3DF` | Заголовки и основной текст |
| `--nora-muted` | `#BFB3BD` | Метаданные, подписи, пояснения |
| `--red` | `#FF0750` | Буква «О», капля активной вкладки, красные акценты и кольца фокуса |
| `--on-red` | `#111013` | Текст и иконка на красной подложке |
| `--red-text` | Смесь `--red` с белым или `--on-red` | Акцентный текст и ссылки на тёмных и светлых поверхностях |
| `--nora-line` | `rgb(255 243 223 / 12%)` | Тонкий разделитель, край всплывающей поверхности |
| `--nora-control-edge` | `#817380` | Видимая граница текстового поля там, где она нужна для распознавания |
| `--nora-success` / `--nora-warning` | `#91D6AD` / `#F1C87F` | Статус с текстом или пиктограммой |

Обычная строка лежит прямо на фоне или в общей панели вместе с соседними строками. Группу отделяет интервал или один матовый разделитель. Обводка 1 px уместна на поле ввода, всплывающей панели или там, где край функционально важен. Поднятие задаётся тоном поверхности и мягкой нейтральной тенью, например `0 8px 28px rgb(0 0 0 / 32%)`. Полупрозрачность видна на краях фотографий и поверх соседнего слоя. Начальный лимит для `backdrop-filter` — один видимый слой 8 px на верхнем диалоге, со сплошным fallback. Карточки ленты, вложенные поверхности и анимированные слои используют заливку. Обложки получают локальную затемняющую подложку, если текст идёт поверх изображения.

Тёмный текст на сплошном фирменном красном даёт 4,87:1. Для мелкого красного текста используется `--red-text`. Проверять контраст на итоговой поверхности, в том числе поверх обложек. Цель — 4,5:1 для обычного текста и 3:1 для крупных надписей и необходимых границ и пиктограмм.

## Типографика и ритм

| Роль | Размер / строка | Вес / шрифт |
| --- | --- | --- |
| Название страницы | 28–32 / 34–38 px | 750–800, локальный Rubik |
| Заголовок секции | 20 / 26 px | 700, Rubik |
| Название строки или карточки | 16 / 22 px | 650–700, системный sans |
| Основной текст и поля ввода | 16 / 24 px | 400–500, системный sans |
| Метаданные | 13 / 18 px | 450–550, системный sans |
| Короткая вторичная метка | 12 / 16 px | 550–600, системный sans |
| Баланс, цена, рейтинг | 20–24 / 26–30 px | 700, по возможности `tabular-nums` |

Rubik уже используется в основных вкладках. Monocraft остаётся у пиксельной игры и её характерных элементов. Подключения дополнительных веб-шрифтов не требуется. Длинные имена, цены на узких экранах, даты и заголовки переносятся естественно. Значимые данные доступны полностью в карточке, деталях или подписи.

Шаги интервалов — 4, 8, 12, 16, 20, 24 и 32 px. Внутри строк 8–12 px, внутри панели 12–16 px, между секциями 20–24 px. Боковое поле 12 px при ширине до 360 px, 16 px на обычном телефоне, 20 px на широком экране. Радиусы 12 px для контролов, 16 px для панелей и 22 px для диалогов. Нижнее поле контента рассчитывается от фактической панели навигации и safe area. Верхний inset Telegram сохраняет приоритет. Кнопки и строки имеют область касания от 44×44 CSS px, с целью 48 px для основных мобильных действий. Видимая иконка 20–24 px. У точек карусели увеличить хитбокс отдельной проверкой взаимодействия с соседними точками.

## Компоненты

| Компонент | Правило |
| --- | --- |
| Заголовок вкладки | Заголовок, опциональное действие или одна строка контекста. Сезонную метку показывать там, где она объясняет контент. |
| Строка действия | Иконка или аватар, заголовок, при необходимости метаданные, значение или стрелка. Вся строка активна, в группе один общий контейнер. |
| Карточка с обложкой | Обложка с зарезервированным размером, заголовок, короткие метаданные, одно главное действие. Цена и доступность видны до открытия подтверждения. |
| Кнопки | Красная основная, тёмная вторичная с ясным контуром состояния, текстовая для переходов. Для ожидания и ошибки сохранять понятную подпись. Фокус виден; состояние не передаётся одним цветом. |
| Раскрытие и список | Существующие `details/summary` для рейтинга, команды и дополнительных данных. Строки идут плотной группой, состояние и фокус сохраняются при обновлении. |
| Диалог | Одна шапка, доступное закрытие, заголовок, содержание, нижнее действие при необходимости. Проверять Escape, Telegram Back, возврат фокуса и клавиатуру. |
| Пусто / загрузка / ошибка | Пустое состояние в естественном месте, объяснение и доступное действие. Загрузка резервирует высоту. Повтор операции сохраняет контекст, поля формы и статус запроса. |

## Движение

- Нажатие — 100–140 мс, появление состояния или панели — 160–220 мс, закрытие — 120–160 мс, раскрытие — до 240 мс. Базовая кривая `cubic-bezier(.2,.7,.3,1)`, амплитуда появления 4–8 px. Анимировать `transform` и `opacity` в небольшом числе элементов.
- Учитывать `prefers-reduced-motion`: сразу показать конечное состояние, убрать декоративное движение и сохранить текстовую обратную связь. Существующий haptic на осмысленном нажатии сохраняется.
- Капля нижней навигации перемещается под выбранную вкладку с существующей анимацией дока. Блик поверх фирменного красного поддерживает стеклянное оформление.

## Критерии реализации

- Прогон на 320, 360, 390, 430 и 768 CSS px. Для 390 px — обычное состояние, длинный контент, клавиатура и reduced motion. Проверить обе ориентации, реальные safe areas и Telegram Back на iOS и Android.
- У текстовых и визуальных состояний есть подписи, видимый фокус и сохранение семантики кнопок, ссылок и диалогов. Никакого горизонтального скролла страницы, кроме явно обозначенной внутренней ленты.
- Сохранить контракты API, правила доступа, маршруты, подтверждения и ролевые действия. Держать дизайн игровой сцены и её HUD в отдельной области CSS.
- Снять сравнительный trace на одинаковом наборе данных: первый рендер всех пяти вкладок, скролл списка и быстрое переключение вкладок. Цели — CLS ≤0,10, отсутствие новых задач main thread >50 мс на этих взаимодействиях при одинаковом профиле 4× CPU, отсутствие роста начальной передачи CSS/JS. Использовать существующие ассеты, lazy loading там, где медиа вне первого экрана, и пространство под изображения до их загрузки.
- Удалять устаревшие правила после миграции последнего потребителя и визуального сравнения. Общие токены, состояния и размеры объявлять один раз. Не добавлять новый runtime ради анимации и стилизации.
