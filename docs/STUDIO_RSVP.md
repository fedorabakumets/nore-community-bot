# Студия постов и запись на события · обновление 19

## Причина жалобы

Оба обработчика `post:rsvp:yes/no` вызывали `_show_post_preview`, который
импортировал несуществующий `posting.rsvp_preview_block`. Возникал ImportError
до отправки предпросмотра и кнопки публикации. Ошибка воспроизведена через
Dispatcher с настоящими фильтрами обработчиков в четырёх комбинациях:
RSVP / без RSVP × с опросом / без опроса.

## Поведение

- Оба выбора открывают предпросмотр; запись в предпросмотре недоступна.
- Опубликованный пост показывает `Я буду (N)`. Один человек считается один раз.
- Новый пользователь регистрируется автоматически при нажатии; предварительный
  `/start` для бесплатной записи в группе не требуется.
- Повторное нажатие не снимает запись случайным двойным кликом: оно показывает
  отдельное подтверждение отмены, доступное только этому человеку.
- Ненулевой залог требует подтверждения. Его сумма закреплена за постом при
  публикации, а не меняется вслед за глобальной настройкой.
- Отмена возвращает залог в одной транзакции с удалением записи и записью
  возврата в журнал. Повторное подтверждение не возвращает деньги дважды.
- Оплата билета учитывает уже внесённый залог; доплачивается только разница.
  Если залог больше цены билета, излишек возвращается той же транзакцией.
  Обычная запись сама по себе не считается оплатой. Цена повторно проверяется
  в транзакции. Оплаченный билет требует ручного обращения к организаторам.
- Кнопки-ссылки и оплаты сохраняются при изменении счётчика.
- Повторная попытка после ошибки отправки опроса не отправляет пост заново
  в рамках текущего черновика. Незавершённые черновики по-прежнему хранятся
  в MemoryStorage и теряются при перезапуске.

Администратор открывает **Админ-панель → Чат → События и участники**.
Список постов разбит на страницы по 8, участников — по 10. В карточке события:
число людей, имена со ссылками на профили, username при наличии, запись /
залог / оплата, кнопка открытия исходного поста. Доступ требует `chat.post`
и доступа в админ-панель; в группе личный список не публикуется.

## Хранение и совместимость

- Новая таблица `studio_events`: исходный пост, заголовок, ссылки, режим RSVP,
  сумма залога, автор и признак необходимости обновить кнопки.
- В `event_rsvps` добавляется `kind`: `rsvp`, `payment`, `legacy`.
  Старые строки и финансовый журнал не переписываются. Старые положительные
  списания имеют неоднозначное назначение и не возвращаются автоматически.
- Архивные события из `event_rsvps`/`event_offers` доступны в админке даже без
  новой метаинформации. Название неизвестного старого события — его ID.
- Старый общий пост привязывается при первом нажатии на исходную RSVP-кнопку
  в настроенном чате сообщества. Для него используется текущий глобальный залог,
  потому что историческая сумма в старом коде не фиксировалась.
- Изменения записи и оплаты выполняются через `BEGIN IMMEDIATE`, уникальность
  обеспечивается ключом `(event_id, user_id)`. Посты используют случайные ID.
- Обновления Telegram сериализованы для каждого события в одном процессе.
  `markup_dirty=1` переживает API-сбой и рестарт: штатный процесс повторяет
  обновление каждые 30 секунд. Для удалённых/недоступных редактированию сообщений
  автоматические попытки прекращаются (`-1`); список участников сохраняется.

## Проверка и выпуск

`tests/test_studio_rsvp.py` использует временную SQLite, Dispatcher и поддельную
сессию Telegram без сети. Проверяются публикация текста/фото с опросом в обоих
режимах, счётчик, конкурирующие клики, отмена и возврат, доплата за билет,
проверка цены и баланса, права и страницы списка, сбои API, повторная отправка,
старый пост и обновление старой схемы без изменения балансов/журнала.

Перед выпуском нужен новый согласованный backup. Существующий
`NORA_PRE_RELEASE_BACKUP_ONCE` позволяет получить приватную SQLite-копию и
проверить восстановление до `initialize`; используйте новый идентификатор
релиза. Предыдущую точку восстановления не перезаписывать.

После разрешённого выпуска: убедиться в SUCCESS Railway, старте polling,
отсутствии новых ошибок; организатор проверяет реальное создание события и
список на своём посте. Автоматические тесты не обращаются к production Telegram.
Откат кода — на коммит обложек `cf0fa1f6ff0457acf9e9473b527e2e17505b5666`.
Добавленные таблица/столбец совместимы со старым кодом; откат кода не отменяет
новые записи, оплаты и возвраты. Восстанавливать старую БД поверх новых действий
участников нельзя без отдельного плана переноса данных.
