# Цвета inline-меню

## Личные чаты: RichMessage

Все личные экраны используют `private_rich.py`: одно сохраняемое сообщение с
`InputRichBlockButtons` / `RichMessageButton` внутри содержимого. Переходы между
разделами, анкета, профиль, кошелёк, магазин, поддержка и админские действия
редактируют эту панель через `editMessageText(rich_message=...)`.

- Обычные переходы и возврат — `link`: цветной текст без рамки/заливки,
  оттенок задаёт Telegram. Подтверждения — `success`, опасные действия — `danger`.
- Ссылки и Mini App открываются прежними URL; явно заданный цвет ссылок сохраняется.
- На главной только разделы; в остальных экранах действия раздела и один «Назад».
  Дубли callback/URL удаляются, лишнее «Закрыть» не показывается; существующий
  возврат во вложенный раздел имеет приоритет перед возвратом в главное меню.
  Панель создаётся без reply_markup:
  ReplyKeyboardRemove/ReplyKeyboardMarkup запрещены, чтобы сохранить возможность
  редактирования. Доступ гостей и проверка прав сохранены.
- Во время ввода «Назад» отменяет действие или открывает родительский раздел;
  для анкеты остаётся перезапуск.
  Фоновое уведомление сохраняет текущий вопрос и управление диалогом.
- Фото, видео, аудио, документы и голосовые вложены в Rich-блоки. Длинные карточки
  не делятся по прежнему лимиту подписи фото. Стикер-пак открывается Rich-кнопкой.
- Декоративные обложки разделов в личке убраны; аватары и реальные вложения остаются.
  Профили в личке компактные, без рамок и шкал, в том числе с включённым ornate.
  Лишние пустые строки и линии-разделители убираются; pre/code сохраняют переносы.
- Несколько ответов одного обработчика собираются в одну страницу. ID и содержимое
  хранятся в существующем `bot_state`; после перезапуска панель переиспользуется.
  /start (включая ссылки с параметром и «старт») заново открывает панель: удаляет
  прежнюю по возможности и отправляет одну новую. Это восстанавливает чат после
  локального удаления, о котором Bot API не сообщает. Если Telegram запрещает
  удаление старого сообщения, /start всё равно создаёт видимую панель.
  Остальные переходы редактируют её; новая отправка нужна при первом открытии
  либо если Telegram сообщает, что прежнее сообщение удалено.
  Не редактируемая панель предыдущей версии однократно удаляется перед заменой;
  если удалить её нельзя, новое сообщение не отправляется. Другие ошибки
  редактирования и сетевые ошибки не создают копий.
- Старые сообщения автоматически не удаляются; их кнопки после создания новой
  панели предлагают открыть актуальную панель или `/start`.
- Обновление сообщения не создаёт отдельного push-уведомления Telegram.

## Групповые inline-меню

Встроенные inline-меню используют общую политику `inline_style.py`, применяемую
перед отправкой и редактированием Telegram-сообщений. Навигация, выбор разделов,
игр и сумм — стандартный нейтральный цвет Telegram. Конкретные белый/серый/тёмный
оттенки задаёт тема клиента: Bot API не позволяет назначить произвольный RGB.

Назад, закрытие, отмена и отрицательные действия — красные; подтверждение и
положительные действия — зелёные. Цветовые состояния переключателей сохранены.
Клавиатура под полем ввода, пользовательские ссылки постов и общие RSVP-посты
сохраняют прежнее оформление. Callback data, ссылки, порядок и число кнопок
не изменяются. Новые цвета появляются при новом открытии/обновлении меню;
массовое редактирование старых сообщений не выполняется.
