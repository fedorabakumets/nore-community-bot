## Проверки

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python tools/check_local.py
.venv/bin/python -m pip check
```

check_local.py блокирует Python socket connections/DNS на время pytest.
Это защита существующих Python tests, не общий sandbox внешних CLI.
Не добавлять тесты, запускающие реальные сервисы или внешние сетевые команды.
Для интеграционных проверок использовать отдельные бот, чат и базу.

Production DB integrity, restore test, Docker build и живые Telegram-сценарии
не проверялись. Пакеты установлены по диапазонам pyproject и могут отличаться
от зависимостей уже развёрнутого образа.

## Выпуск только после отдельного разрешения

1. Сверить SHA и настройки Railway, создать отдельную feature-ветку.
2. Подготовить патч, релевантные tests, diff/PR и план отката.
3. До push проверить branch/PR deployment triggers: Cursor-ветка запускает production.
4. При изменении БД согласовать консистентный backup и restore test с учётом WAL.
   Откат кода не откатывает данные.
5. Получить разрешение на конкретную публикацию; после deploy проверить updates,
   errors, фоновые задачи и сохранность данных.

Предлагаемый будущий процесс: protected release-ветка, обязательные CI checks,
отдельная staging-среда/бот и approval production. Настройки пока не менялись.

Не копировать работающий .db простым copy как гарантированно корректный backup:
использовать SQLite backup API либо согласованный snapshot с учётом WAL.
Checkout не содержит рабочей базы. initialize() создаёт новую пустую базу.

## Однократный сброс профиля для повторной анкеты

NORA_RESET_PROFILE_ONCE — JSON с username (без @) и уникальным nonce.
Это обслуживающая переменная Railway, не публичный API и не команда участника.
Перед включением требуется прямой запрос владельца на конкретный аккаунт.
В обычном выпуске значение должно оставаться пустым.

Startup проверяет точное совпадение ника через Telegram getChat, защищает
аккаунты OWNER_IDS/MODERATOR_IDS и требует ровно одну подтверждённую личность.
До изменений создаётся приватный SQLite backup на volume с проверкой integrity
и восстановления. В транзакции очищаются поля карточки/репутация/варны,
выставляется member, прежние approved/pending анкеты архивируются как reset,
сохраняются marker однократности и запись журнала от системного исполнителя.
Баланс, долг, ledger, оплаты, питомец, друзья, заявки розыгрыша и факт уже
полученного бонуса профиля сохраняются. Повторное заполнение не даёт бонус снова.
Удаления users и других бизнес-записей нет. Старая анкета не блокирует новую.

После проверки статуса done в логах и запуска polling оператор очищает переменную
без дополнительного развёртывания. Запрос с тем же username/nonce не сбрасывает
повторно уже начатую новую анкету. При неподтверждённом нике, конфликте прав или
ошибке backup изменения не применяются; ошибка обслуживания не останавливает бота.
После сброса пользователь отправляет /start в личке. Mini App закрыта, пока роль
остаётся member; новые права назначаются штатным способом отдельно.
