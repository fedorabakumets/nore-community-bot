# Передача проекта владельцу

Никакие аккаунты, роли, данные, платежи и production-настройки пока не менялись.

| Актив | Установлено | Что подтвердить |
|---|---|---|
| GitHub | fedorabakumets, публичный repo, push=false | Write и Transfer ownership |
| Railway | nora-community-bot, workspace My Projects | Owner/admin, billing, GitHub integration identity |
| Telegram | @nora_community_bot, long polling | BotFather ownership и владелец сообщества |
| SQLite | Роли, балансы, заявки, Telegraph token | Backup, restore, аудит старых staff-ролей |
| СБП | Ручные заявки и прежний fallback в config | Получатель, права владельца, новые реквизиты |
| Приглашение | Старая ссылка в config | Принадлежность чата, актуальная ссылка |
| Telegraph | Token в bot_state | Доступ к страницам и защищённый backup |
| Gemini/Groq/TMDB | Необязательные ключи поддерживаются | Использование, владельцы аккаунтов и биллинг |

## Последовательность

1. Подтвердить аккаунты пользователя, 2FA, текущих владельцев и recovery-контакты.
2. Получить Write, согласовать ветки и контролируемый release-процесс.
3. Согласовать консистентный backup SQLite и restore в изоляции, включая WAL
   и bot_state. Не публиковать DB в Git.
4. Передать GitHub repo штатным Transfer ownership с историей, ветками и
   настройками; проверить GitHub Apps и Railway integration.
5. Подготовить передачу Railway с сохранением volume/billing. Если требуется
   новый проект, отдельно планировать перенос данных и окно переключения.
6. Передать BotFather ownership и сообщество. По возможности сохранить того же
   бота: media file_id могут не работать с новым Telegram-ботом.
7. Проверить users.role и staff_roles на копии. Удаление ID из OWNER_IDS
   не снимает сохранённый owner: нужен отдельный согласованный отзыв роли,
   проверка admin/moderator/custom permissions.
8. Подтвердить и заменить СБП-ссылку, приглашение и внешние API-ключи.
   Реальные реквизиты менять только после подтверждения получателя.
9. Согласовать переключение: один production poller, DATABASE_PATH на volume,
   резервная копия, проверки данных и rollback.
10. После приёмки отозвать старые developer доступы и заменить ключи,
    включая переданные в переписке. Ротация production требует разрешения.
    Настроить защищённое хранение секретов для последующих сессий ChatGPT.

Завершение: пользователь контролирует GitHub, Railway/billing, BotFather,
сообщество, платежи, данные и backups; старые права отозваны, работа и restore
проверены. ChatGPT готовит изменения в отдельных ветках с tests, а публикация
происходит только по разрешению пользователя.
